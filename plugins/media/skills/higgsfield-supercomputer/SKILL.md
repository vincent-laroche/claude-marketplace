# Higgsfield Supercomputer

Read `../../references/production-contract.md` before executing a plan. Supercomputer can coordinate creative work and external connectors, so a natural-language brief is not permission to publish, send, schedule, or connect services.

## Start with an operating brief

State the outcome, accepted deliverables, source assets, brand/project context, model preference if any, review gate, destinations, and prohibited actions. Ask Supercomputer to propose the workflow before it executes whenever that workflow would create assets, use connectors, or schedule work.

## Treat each capability separately

- **Skills:** reusable workflows; inspect their exact scope and outputs before installing or invoking one.
- **Files and memory:** confirm which project contains the source of truth before asking it to reuse a prior asset or direction.
- **Connectors:** identify what it can read, create, or post in each external service. Never grant broad access merely to discover a file.
- **Scheduled tasks:** write the cadence, input source, output location, recipient/channel, budget behavior, and pause/stop condition. Get explicit approval before enabling.
- **Model routing:** automated model selection may be useful, but the live model inputs, controls, and user-authorized scope still govern the run.

## Approval-safe production loop

1. Request the proposed workflow and output inventory.
2. Review its selected assets, model path, connector actions, and output destination.
3. Approve only the bounded execution that Vincent wants.
4. Inspect output in the named project; do not infer completion from a chat message.
5. For repeated work, promote a reviewed workflow to a skill/schedule only after its first manual run succeeds.

Use Canvas for a graph Vincent needs to inspect or reuse visually; use Cinema Studio for directed shots; use Supercomputer for bounded orchestration across creative work, files, skills, and approved external tools.
