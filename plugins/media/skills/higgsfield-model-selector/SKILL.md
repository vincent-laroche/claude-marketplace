# Higgsfield model selector

Read `../../references/model-selection.md` and `../../references/production-contract.md`.

## Start from the hard requirement

Extract:

1. final deliverable and crop;
2. protected identity, product, or visual-system attributes;
3. required input type: text, image, multiple references, motion video, first/last frame, or existing footage;
4. motion, scene, camera, audio, text, and localization needs;
5. whether the output is one asset, a recurring character, a multi-shot sequence, or an editing insert.

Choose the model whose native input and control system addresses the hardest requirement. Do not recommend a model merely because it is newer or visually impressive.

## Return a decisive route

State:

- **Primary route:** model or surface and why it fits.
- **Input pack:** exact assets to prepare and each asset's role.
- **Prompt structure:** information the model should receive.
- **Review gate:** the defects that would disqualify an output.
- **Fallback:** the next model only if the primary route fails on a named criterion.

Use a two- or three-model comparison only when the brief has real ambiguity. Hold the source assets, intent, aspect ratio, and review rubric constant. Select a winner for the shot class rather than declaring a universal best model.

Route to the model-specific skill before execution.
