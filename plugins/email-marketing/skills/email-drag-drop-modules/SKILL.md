# Email drag-and-drop modules

1. Run email-marketing-preflight. Read ../../references/authority-map.md,
   ../../references/tool-routing.md, and ../../references/email-quality-gates.md.
2. Inspect the approved brief or source design and create a module inventory before touching the
   dashboard: header, hero, text, image-text, product, proof, CTA, FAQ, spacer, and footer as needed.
3. Prefer native MailerLite blocks for ecommerce, unsubscribe, preferences, personalization, and
   dynamic content. Keep marketer-editable text and imagery editable.
4. Use a signed-in browser for drag-and-drop composition and Save as template. The public API and MCP
   can list email templates but do not prove native template authoring parity.
5. Name modules by purpose, not campaign. Test reuse in a disposable draft before promoting a template.
6. Verify mobile stacking, image crop, padding, CTA behavior, dark mode, merge fields, and block
   editability. Compare against the source at equivalent widths.
7. Return module inventory, template location, browser evidence, editable fields, and known MailerLite
   constraints.

Do not schedule, send, publish a form, or activate an automation while building modules.
